# ADR-0007 · 编排层留在 BullMQ，明确 Temporal 的迁移触发条件

- **状态**：已接受（修正早期调研备忘录中「用 Temporal」的建议）
- **日期**：2026-08-10
- **相关**：`05-job-orchestration.md`

## 背景

早期技术备忘录推荐用 Temporal 承担生成、评测、重试、审批的长事务。当前设计实际采用 BullMQ + Postgres 真相源 + 手写状态机 + 启动时 reconcile。需要就此做一次明确决策，而不是让两种说法并存。

系统的任务特征：单次生成 30 秒–5 分钟、成本 $0.01–1、失败需按策略升级重试、一集 10–25 镜并发、**有人工选片门可能等数天**、有末帧接首帧的依赖、需要三层限流与成本记账。

## 决策

**MVP 到 M5 阶段（端到端闭环）留在 BullMQ + Postgres 状态机，不引入 Temporal。** 同时把迁移触发条件写进本 ADR，避免「什么时候该升级」变成一个反复争论的开放问题。

## 理由

**核心难点不在编排引擎。** 本系统最难的部分是「一部剧是一个存活数周、带人工评审门的领域实体」——这个状态机无论用什么引擎都必须存在于 Postgres 里，它是产品的数据模型，不是可以外包给编排器的管道逻辑。Temporal 擅长消灭的是「机器到机器的多步 saga 样板代码」，而这在本系统中占比很小。

**成本不是问题，认知负担才是。** 按本项目量级（一部剧 800–2500 镜头 ≈ 0.8–2.5 万 actions，每月 10 部 ≈ 8–25 万 actions）估算，Temporal Cloud 的实际支出就是 Essentials 层 $100/月的地板价，用量本身几乎免费。真正的代价是 **determinism 约束 + 工作流版本管理**：工作流存活数周，而 MVP 期流程逻辑每周都在改，每次改动都要考虑对在飞工作流的 patch。这两者相乘，成本远高于典型微服务场景。

**反向证据。** ToolJet 是**从 Temporal 迁回 BullMQ** 的，公开的迁移文档给出的理由是「无需单独部署 Temporal server」「复用现有 Redis」「基础设施成本更低」。

**正向案例的前提条件不成立。** Descript（51–250 人）与 VEED.IO（170+ 人、日均 400 万 activities）确实靠 Temporal 解决了问题，但两者的共同点是：都有**专职平台团队**、都是**先有一个每周出一次生产事故的手写系统**才迁移的。本项目当前既无该痛点，也无该团队。

## 迁移触发条件（满足任意 2 条即启动评估）

1. 状态机相关代码超过约 2000 行，或新增一个流程分支需要改 ≥3 个文件
2. 因状态不一致导致的线上问题累计 ≥3 次
3. ≥3 名后端开发同时修改工作流逻辑，需要对工作流本身做单元测试
4. 需要「把 N 个失败流程批量重置到第 K 步重跑」的运维能力，且已手工做过 ≥2 次
5. provider / project 维度的动态限流已长成一坨不敢改的代码

## 届时的选择顺序

1. **Hatchet** —— 唯一同时满足三条关键需求的：Python 与 TypeScript 双一等 SDK、**只依赖 Postgres**（可顺带干掉 Redis）、基于 CEL 表达式的 concurrency key（直接解决全局/provider/project 三层限流）。内置 replay UI。风险是公司年轻、生产案例少于 Temporal。
2. **Temporal Cloud**（不是自托管）—— 前提是届时已有第二名后端开发、且业务流程已稳定（determinism 与 versioning 的代价才降下来）。
3. **自托管 Temporal** —— 仅在有专职运维时考虑。注意 **History Shards 数量初始化后永久不可改**。

## 明确否决：BullMQ 与 Temporal 混合

两套真相源会派生出第三套对账逻辑，两套重试/超时/限流语义会让调参无从下手，两套可观测性会让排查一个失败镜头要在两个 UI 之间跳。**当前设计最大的优点是 Postgres 单一真相源，不能为了引入编排器而毁掉它。** 若真要迁移，只允许「新流程走新引擎、老流程限期迁完」的过渡期，不允许长期共存。

## 后果

**正面**：基础设施保持三件套（Postgres / Redis / MinIO）；迭代速度不受 determinism 约束拖累；单一真相源。
**负面**：重试、幂等、reconcile、限流需自己写并自己测；无 replay 与时间旅行调试；800–2500 镜头规模下排障体验弱于 Temporal/Hatchet 的运行时间线。
**缓解**：状态机实现为无 IO 的纯函数以便穷举测试（`03-pipeline.md` §3）；Generation Ledger 承担事后可追溯性（`02-data-model.md` §4）。
