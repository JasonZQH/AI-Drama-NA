# Web 端定位与管理面板设计

> Status: 已确认 · 2026-08-15 · 依赖：`07-design-system.md`、`08-screen-specs.md`、`02-data-model.md`

## 1. 背景：一个必须解决的定位矛盾

文档里关于 web 的四处表述互相拉扯：

| 出处 | 说的是 |
|---|---|
| `07` §1 | 「不是内容网站，是生产工具」——参照 DaVinci / Linear，不是 Netflix |
| `08` §7 | 播放器是「成品验收视角」，给生产者用 |
| `00` §2.5 | 分发路径是免费平台引流 → **自有 App/Web 转化** |
| `12` 明确不做 | 「Web 结账在架构上须预留（TV-MA 完整版的唯一合法通道）」 |

前两条把 web 定义为内部工具，后两条把它定义为商业模式的收口。M0 阶段这两者共用一个 Next.js app（`(studio)` 与 `(watch)` 两个路由组），但它们的要求几乎处处相反：暗色高密度 vs. 沉浸竖屏、键盘优先 vs. 拇指优先、单人无认证 vs. 多用户带支付与年龄门控。

## 2. 定位决策

**Web = 管理面板（admin panel），不是消费产品。**

生产者通过它查看项目内生成的 prompts、资产、镜头与花费；主页给出跨项目的经营数字；将来接入投放与收入。

`(watch)` 路由保持「成品验收视角」不变——生产者用观众的眼睛自查的工具。**真正的消费端（付费观众、Web 结账、年龄门控）不在本设计范围内**，何时以何种形态建，留待 M1–M2 的成本数据出来后另行决策。

这条决策消解了 §1 的矛盾：`07`/`08` 描述的是本面板，`00`/`12` 描述的是另一个尚未开工的产品。

## 3. 导航结构

```
主页（工作台）
  └─ project 标签页 → 分集列表（标题 / 进度 / 花费）
       └─ episode 标签页 → 镜头网格
            └─ 镜头抽屉 → prompt · takes · Generation Ledger
```

**新增的一级是分集列表。** 当前的分镜页直接取 `episodes[0]`，这在 80–100 集的真实剧集下不成立。

### 3.1 应用内多标签栏

采用「全挂载 + CSS 隐藏」：workspace 外壳持有标签注册表，所有打开的标签同时挂载，非活跃的以 `hidden` 隐藏。

**为什么不用「路由驱动 + 状态快照」**：状态保留是多标签这个模式存在的全部理由，而快照方案只能保留你事先想到要保存的字段——视频播放位置、填了一半的表单、展开的抽屉都会丢。且每加一个有状态的组件都要记得去 store 登记一次，是持续的维护税。

**为什么不用 iframe**：SSE 连接数乘以标签数、快捷键与主题跨 frame 难协调、深链几乎做不了。

**约束**：
- 标签上限 **12**，超出时关闭最久未活跃的一个并提示
- URL 同步活跃标签，刷新与深链成立
- **SSE 是 shell 层单条连接**，按 `projectId` 分发给各标签，不是每标签一条
- 镜头网格必须虚拟化——这是全挂载方案的内存前提，且 `07` §6.2 本就要求（资产可能几千个）

## 4. 主页

顶栏常驻生产状态（`⚡ N running · M queued` + 今日预算条），主体四块：

**经营快照**：总花费、项目数、总镜头、每可用镜头成本。同一行预留投放 / 收入 / ROI 三个位置，当前显示 `—`。

**趋势**：每日花费与一次通过率。
- 默认 **30 天**
- 可选 **3 个月 / 6 个月 / 1 年 / 全部**
- **粒度随区间自动切换**：≤90 天按日，≤1 年按周，全部按月。365 个日粒度点在一张卡片宽度里既读不出趋势也画不清

**需要你处理**：失败镜头数、待选片数。点击直达对应筛选态，不是跳到列表让人自己找。

**项目列表**：每行带镜头数、花费、进度。

## 5. 后端新增

现有 API 撑不起主页，需要两个端点。

### 5.1 `GET /api/stats/overview`

```jsonc
{
  "totals": {
    "projects": 3,
    "shots": 1847,
    "costMicroUsd": 18420000,
    "usdPerAcceptedMicro": 210000
  },
  "attention": { "failedShots": 3, "pendingReview": 12 },
  "queue": { "running": 6, "queued": 18 },
  "budget": { "spentTodayMicroUsd": 2140000, "dailyLimitMicroUsd": 5000000 },

  // 可扩展性的落点：现在就存在，M4 接投放回传时是**填充**而非改结构
  "distribution": null,
  "revenue": null
}
```

### 5.2 `GET /api/stats/timeseries?range=30d|3m|6m|1y|all`

```jsonc
{
  "range": "30d",
  "granularity": "day",          // day | week | month，由 range 推导
  "points": [
    { "at": "2026-08-01", "costMicroUsd": 420000, "attempts": 24, "accepted": 14 }
  ]
}
```

一次通过率由 `accepted / attempts` 在前端算，不预先算好——这样同一份数据也能画尝试次数。

### 5.3 项目列表要带聚合

现有 `GET /api/projects` 只返回裸行。改为附带每项目的镜头数、花费、状态分布，避免前端 N+1。

## 6. 可扩展性的落点

**可扩展性体现在响应形状，不在页面结构。**

`overview` 现在就带 `distribution: null` 与 `revenue: null`。M4 接入投放回传时是填充这两个区块，前端卡片的位置与类型都不用动。代价只是两个 null 字段，收益是避免一次结构性改动。

数据来源侧：`renders` 表已有 `impressions / installs / spendMicroUsd / d0Roas` 四列（`02` §8.5），但目前没有任何写入方——这是 issue #8 覆盖的缺口，不在本设计范围。

## 7. 动效

`frontend-design` 的告诫是：把大胆用在一个地方，其余保持安静，否则会显得是模板生成的。

**唯一的编排时刻**：页面载入时趋势曲线从左向右画出，**累计总花费的数字与曲线同步递增**，曲线到达右端时数字恰好停在当前值。

这不是装饰——它陈述了一件真的事：**那个数字就是这条曲线的积分**。

其余只保留功能性最小动效：
- 标签切换的位移
- 卡片入场的轻微 stagger
- 进度条过渡

全部通过 `gsap.matchMedia()` 尊重 `prefers-reduced-motion`（`07` §8 的可访问性底线）。

## 8. 沿用不变

- `07` 的全部色彩/排版/间距令牌
- 三条硬规则：R1 进度必须可读、R2 花钱必须二次确认且显示金额、R3 失败必须可操作
- 状态胶囊必配图标或文字，绝不只靠颜色
- 所有数字 `tabular-nums`

「参考成熟 admin」指的是**信息架构与标签栏行为**，不是换一套视觉语言。现有令牌是为「长时间盯视频缩略图」这个场景选的，换掉会亏。

## 9. 不在本设计范围

| 不做 | 原因 |
|---|---|
| 消费端产品（付费观看、Web 结账、年龄门控） | 定位已明确它是另一个产品，待 M1–M2 数据后另议 |
| 剧本页 | 需要 LLM provider 契约（issue #6），M1+ |
| 剪辑页 | 需要音频（M3） |
| 素材页 / ROAS 面板 | 需要投放回传写入方（issue #8），M4 |
| 资产页的**编辑**能力 | 本轮只做查看；锁定闸门的交互见 issue #16 |

## 10. 验收

- 主页在无数据、单项目、多项目三种状态下都给出可读画面（空态要给下一步动作，不能只说「暂无数据」）
- 打开 12 个标签后仍可交互；第 13 个触发最久未用关闭并提示
- 关闭浏览器重开，活跃标签可由 URL 恢复
- 趋势切到「全部」时粒度自动降为月，点数不超过一屏可读范围
- SSE 连接数恒为 1，与打开的标签数无关（可在 devtools 网络面板核对）
- `prefers-reduced-motion: reduce` 下曲线与数字直接呈现终态，不做动画
