## 1. 剧本页 `/projects/[id]/script`

**用途**：S1–S2 阶段，写大纲与分场剧本。

```
┌───────────────────────────┬──────────────────────────────┐
│ 集列表                     │  剧本编辑器                    │
│ ┌───────────────────────┐ │  ┌────────────────────────┐  │
│ │ EP1 逃离  ✓ 已分镜     │ │  │ ## SCENE 1 · 咖啡馆    │  │
│ │ EP2 重逢  ◐ 生产中     │ │  │ [STATE_IN] ...         │  │
│ │ EP3 真相  ● 待分镜     │ │  │                        │  │
│ │ + 新增一集             │ │  │ LIN XIA: 你怎么在这。   │  │
│ └───────────────────────┘ │  └────────────────────────┘  │
│                           │  [AI 生成剧本] [解析为场次]    │
│ 本集元信息                 │                              │
│ 钩子 / 悬念 / 目标时长      │  已解析：3 场 · 预计 92s      │
└───────────────────────────┴──────────────────────────────┘
```

**交互要点**

- 编辑器是 Markdown，按 `03-pipeline.md` §S2 的格式约定高亮 `## SCENE` 与 `[STATE_IN/OUT]`。
- 「AI 生成剧本」调 `POST /api/ai/script`，流式输出到编辑器（用户能看着它写，比转圈好）。
- 「解析为场次」把 Markdown 结构化落 `scenes` 表，解析结果先以 diff 预览呈现，确认后写入——**不静默覆盖用户手写的内容**。
- 钩子类型选择器带提示：连续三集同类型时标黄警告（`03-pipeline.md` §S1 的约束）。

## 2. 分镜页 `/projects/[id]/storyboard` ★ 主战场

用户 80% 的时间在这里。

```
┌──────────────────────────────────────────────────────────────────┐
│ 第 3 集 · 24 镜 · 92s     [筛选: 全部▾] [排序: 顺序▾]  [⌘⏎ 生成整集]│
├──────────────────────────────────────────────────────────────────┤
│ ▾ SCENE 1 · 咖啡馆 · 日 (8 镜 · 31s)              [生成本场]      │
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐        │
│  │#1 ✓│ │#2 ✓│ │#3 ◐│ │#4 ⚑│ │#5 ●│ │#6 ✕│ │#7 ●│ │#8 ●│        │
│  └────┘ └────┘ └────┘ └────┘ └────┘ └────┘ └────┘ └────┘        │
│                                                                  │
│ ▾ SCENE 2 · 天台 · 夜 (9 镜 · 38s)                [生成本场]      │
│  ┌────┐ ┌────┐ ...                                               │
├──────────────────────────────────────────────────────────────────┤
│ 已选 3 个镜头   [批量生成] [换 provider] [跳过]            [取消]  │
└──────────────────────────────────────────────────────────────────┘
```

**交互要点**

- 卡片即 `<ShotCard>`，网格按场次分组、可折叠。悬停自动播放静音预览。
- 点卡片 → 右侧滑出 Shot 详情抽屉（intent 编辑 + PromptInspector + 该镜所有 takes + 生成历史 Ledger）。
- 「生成整集」先调 `POST /api/episodes/:id/generate-batch { dryRun: true }`，用返回值填充 `<ConfirmSpend>`：

```
生成第 3 集
  待生成    18 个镜头（6 个已锁定，跳过）
  依赖阻塞   2 个（等待前序镜头选片）
  Provider  vidu（自动路由）
  预估成本   $3.60      今日剩余预算 $2.86  ⚠ 将超预算
  [取消]  [仍然生成 18 个镜头（约 $3.60）]
```

超预算时确认按钮变 `--status-error` 色，但**不禁用**——是警告不是家长控制，决定权在用户。

- 依赖阻塞的镜头卡片显示锁链图标与 tooltip「等待 #7 选片后自动开始」，前序解锁后自动入队（`03-pipeline.md` §6）。
- 筛选器：全部 / 待生成 / 生成中 / 待选 / 已锁定 / 失败。失败筛选是失败后的第一落脚点。

## 3. 资产页 `/projects/[id]/assets`

**用途**：S4 阶段，建立并锁定一致性资产。这一步没做完，分镜页的批量生成入口应当禁用并给出说明。

```
┌────────────────┬─────────────────────────────────────────────┐
│ 角色 (3)        │  林夏                            v2 ✓已锁定  │
│  · 林夏 ✓       │  ┌──────┐┌──────┐┌──────┐                   │
│  · 陈默 ✓       │  │ 正面 ││ 侧面 ││ 全身 │  [+ 生成更多]       │
│  · 老板 ⚠ 无参考 │  └──────┘└──────┘└──────┘                   │
│                │                                             │
│ 场景 (2)        │  描述（注入每个 prompt）                      │
│  · 咖啡馆 ✓     │  ┌─────────────────────────────────────┐    │
│  · 天台 ✓       │  │ 25岁女性，齐肩黑发，米色风衣…          │    │
│                │  └─────────────────────────────────────┘    │
│ 风格 (1)        │  音色  female-warm-01     [试听]             │
│  · 都市写实 ✓   │  引用于 14 个镜头                            │
└────────────────┴─────────────────────────────────────────────┘
```

**交互要点**

- 未绑定参考图的资产标 ⚠，并在分镜页对应镜头上同步提示。
- 改描述会 `version++`，已锁定的引用镜头显示「资产已更新」角标，**不自动重做**（`03-pipeline.md` §7 的原则）。提供「重做受影响的 14 个镜头」批量入口，由人决定。
- 参考图可上传也可生成；生成走同一套 provider 适配器（图像模式）。

## 4. 选片页 `/projects/[id]/review` ★ 高频重复操作

为键盘操作优化，目标是**一个镜头 3 秒内决策完**。

```
┌──────────────────────────────────────────────────────────────┐
│ 待选 7 个   ◀ #4  林夏抬头看向门口 · CU · 4.0s  ▶            │
├────────────────────┬────────────────────┬────────────────────┤
│  Take 1            │  Take 2  ← 当前     │  Take 3            │
│  ┌──────────────┐  │  ┌──────────────┐  │  ┌──────────────┐  │
│  │              │  │  │              │  │  │              │  │
│  └──────────────┘  │  └──────────────┘  │  └──────────────┘  │
│  vidu · $0.08      │  vidu · $0.08      │  selfhost · $0.01  │
│  T0 ✓  seed 41823  │  T0 ✓  seed 77219  │  T0 ✓  seed 10022  │
│  [1] 选它           │  [2] 选它           │  [3] 选它           │
├────────────────────┴────────────────────┴────────────────────┤
│  ▶ 同步播放  ━━━━━━━●━━━━━━━━  2.1s / 4.0s                    │
│  [R 重新生成]  [X 全部拒绝]  [S 跳过此镜]      [⏎ 确认并下一个] │
└──────────────────────────────────────────────────────────────┘
```

**交互要点**

- 三个 take 同步播放同步进度，便于逐帧对比。
- 快捷键全覆盖（见 `07-design-system.md` §7）。确认后自动跳到下一个待选镜头，形成流水线节奏。
- 「全部拒绝」触发重新生成并升级重试策略（换 seed → 强化 prompt → 换 provider）。
- 显示每个 take 的 provider 与成本——用户会自然形成「哪家在这类镜头上好用」的直觉，这个直觉后续会被 §6 的数据验证。

## 5. 剪辑页 `/projects/[id]/timeline`

```
┌──────────────────────────────────────────────────────────────┐
│  ┌────────────────────┐   预览播放器                          │
│  │                    │   ▶ ━━━●━━━━━━  0:34 / 1:32          │
│  └────────────────────┘                                      │
├──────────────────────────────────────────────────────────────┤
│ 画面 ▐#1▌▐#2 ▌▐#3▌▐#4  ▌▐#5▌▐#6 ▌▐#7▌▐#8  ▌                  │
│ 配音 ▐──▌▐───▌▐──▌▐─── ▌▐░░▌▐───▌▐──▌▐─── ▌  ░=缺失          │
│ 字幕 ▐──▌▐───▌▐──▌▐─── ▌▐──▌▐───▌▐──▌▐─── ▌                  │
│ BGM  ▐──────────────────────────────────────▌                │
├──────────────────────────────────────────────────────────────┤
│ [合成缺失配音 (1)]  [烧录字幕 ☐]  [质量: 预览▾]  [渲染本集]     │
└──────────────────────────────────────────────────────────────┘
```

**交互要点**

- clip 宽度正比时长；拖拽排序，边缘拖拽 trim。
- 缺失配音的 clip 在音轨上以 `░` 标出，一键补齐。
- 渲染分「预览」（720p 快速）与「最终」（1080p）两档；渲染中显示 FFmpeg 进度，失败时可展开日志。

## 7. 播放器 `/watch/[episodeId]`

与 Studio 分离的路由组，是**成品验收视角**——用观众的眼睛看，而不是生产者的眼睛。

```
┌──────────────────────────────┐
│                              │
│         9:16 视频             │
│                              │
│  ▶ ━━━━●━━━━━━━  0:34/1:32   │
├──────────────────────────────┤
│ 第 3 集 · 真相                │
│ ◀ 上一集      下一集 ▶        │
└──────────────────────────────┘
```

竖屏为主，键盘 `←/→` 切集、`Space` 播放暂停。支持 HLS（hls.js）与直接 MP4。这一页刻意做得像消费产品——生产者太容易陷入镜头细节而忘了整体观感，切换到这个视角能发现分镜页发现不了的问题。

## 8. 空态与首次使用

每个页面的空态都要给下一步动作，不能只是「暂无数据」：

| 页面 | 空态文案 |
|---|---|
| 项目列表 | 「还没有项目。创建第一个项目，或载入示例项目（1 集 / 12 镜 / mock provider）。」 |
| 分镜页 | 「本集还没有分镜。先去剧本页写剧本，或直接用 AI 生成分镜。」 |
| 选片页 | 「没有待选镜头。去分镜页生成一些。」 |
| 资产页 | 「还没有角色。角色参考图是一致性的基础，建议先建角色再批量生成镜头。」 |

「载入示例项目」对应 `pnpm db:seed`，是新用户第一分钟就能看到完整流程的关键（`02-data-model.md` §9）。

## 9. 响应式

工具类应用以桌面为主，但要能在 iPad 上审片：

| 断点 | 行为 |
|---|---|
| ≥1440px | 完整布局，分镜网格 6 列 |
| 1024–1440px | 侧栏收为图标，网格 4 列 |
| 768–1024px | 侧栏抽屉化，网格 3 列；剪辑页只读 |
| <768px | 仅开放选片页与播放器，其余引导用桌面 |

剪辑页在小屏不提供编辑——精细 trim 在触屏上做不好，与其做个残废版本不如明确不提供。
